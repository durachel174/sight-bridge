# Phase 0 Plan

## Goal

Decide by the end of Week 3 whether SightBridge should move into a Phase 1 build, pivot to phone-camera-first, or stop.

## Phase 0A: Hardware Feasibility

Answer these in five working days:

- Can the app access live frames from the target glasses at 5 fps or better?
- Can the phone process frames locally before anything leaves the device?
- Can the app provide audio feedback through the glasses?
- Can sessions run for at least 10 minutes without connection instability?
- If any critical item fails, pivot the first prototype to phone-camera-first.

## Phase 0B: Detection Prototype

Use the browser prototype and scenario matrix to measure:

- Alert severity accuracy against 15 scenarios
- False positives on public or impersonal content
- False negatives on financial, medical, identity, and address content
- Latency from capture to disclosure message
- Wording quality for calm, specific alerts

## Phase 0C: User Research

Recruit 8-12 blind and low-vision participants through accessibility communities. Run interviews in parallel with the technical spike.

## Decision Document

At the end of Week 3, write a short go/no-go document with:

- Hardware feasibility
- Detection results
- User research synthesis
- Recommended Phase 1 scope
- Build, pivot, or kill decision
